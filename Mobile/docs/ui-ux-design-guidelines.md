# ToIV 移动端 UI/UX 设计指南

> 版本：v1.0（2026-08-11）
> 适用范围：`ToIV/Mobile/` 全部界面设计、组件实现与走查验收
> 配套文件：[开发规范与流程](development-standards.md) · [ADR 0001 技术选型](adr/0001-tech-stack-react-native-expo.md)
> 用户硬性偏好（最高优先级）：**浅色优先、简洁优雅、视觉对称、克制的物理感动效、UI 退后内容为主、内容配色 ≤5 种、Lucide 唯一图标库**

---

## 一、调研摘要

### 1.1 平台设计规范（双端基线）

| 维度 | iOS（Apple HIG，2025 起含 Liquid Glass 材质） | Android（Material Design 3 Expressive） | ToIV 取法 |
|---|---|---|---|
| 最小触碰目标 | 44×44 pt | 48×48 dp | 统一 **≥48**，图标按钮用隐形热区补足 |
| 返回 | 右缘右滑返回 | 系统返回键/手势 | 双端均须可用，禁止只靠页面返回键 |
| 主导航 | 底部 Tab | 底部 Navigation Bar | 底部 Tab（拇指区） |
| 单位 | pt | dp | 设计稿按 pt，间距 token 双端等效 |
| 材质气质 | 通透、细腻阴影 | 动态色、表达性形状 | 不照搬任一：浅色纸感 + 细腻浮起（Film Atelier） |

平台惯例即用户肌肉记忆：iOS 用户期待滑动返回，Android 用户期待底部导航——违背惯例 = 流失。

### 1.2 用户行为模式（调研结论）

- **单手持机 + 拇指操作**：屏幕下 40% 为舒适区，中 40% 需伸展，上 20% 难达；主操作必须落在**视口下 60%**。因此 ToIV 的「提示词输入条 + 生成按钮」永远贴底。
- **碎片化会话**：移动会话短且随时被打断 → 流程可恢复（草稿持久化、作业断线重连轮询）、状态不丢。
- **耐心红线**：53% 用户放弃加载超 3 秒的页面；首次印象 50ms 内形成且 94% 由设计驱动 → 骨架屏、乐观反馈、冷启动 ≤2.5s 是硬指标。
- **目标越小错误率越高**：<44px 的目标误触率约 3 倍；目标间至少 8px 间距。
- **深色模式普及率 82%**，但本项目**默认浅色**（用户偏好），深色作为平等质量的可选项，不做半成品。

### 1.3 行业最佳实践（AI 创作类 App）

调研对象：Adobe Firefly Mobile、Cliprise、Pika/Krea 系产品及 Shape of AI 模式库：

1. **Prompt-First 首屏**：首页即开放式提示词入口（Initial CTA），配示例与模板脚手架，零学习成本发起首次创作。
2. **示例画廊（Example Gallery）**：展示「结果 + 提示词 + 参数」，一键「试试这个」带入创作——既是新手引导也是能力橱窗。
3. **参数调优器（Tuner）**：高级参数收进底部抽屉/二级面板，默认只暴露「模型、比例、数量」，复杂度渐进披露。
4. **生成状态全程可见**：作业卡片实时进度、完成推送通知、失败给出可操作的恢复动作（重试/改参），历史跨端同步。
5. **作品库即作品集**：网格画廊 + 全屏详情（提示词/模型/参数可查可复用），下载/分享/再创作一步到位。

## 二、设计原则（8 条，按优先级）

1. **内容至上，UI 退后**（Film Atelier 方向）：界面是暗房与剪辑台，作品才是主角； chrome 元素克制收敛，无作品时不炫技。
2. **浅色优先**：默认浅色主题，纸感底色 + 细腻层次；深色同等打磨。
3. **视觉对称**：主轴对称、留白成对、网格对齐；不对称构图需走查豁免。
4. **拇指可达**：主操作沉底，危险操作上移并二次确认。
5. **渐进披露**：默认只给最常用的 3-5 个控件；高级参数收进抽屉。
6. **状态诚实**：加载/生成/失败/空，每个异步状态都有明确、可操作的呈现，不假装成功。
7. **克制的动效**：动效服务理解与反馈，物理感、呼吸感；时长 ≤300ms；**禁止**高饱和彩虹粒子、大面积闪烁、粒子爆炸、快速频闪、粒子遮字等一切炫技。
8. **可访问即底线**：WCAG 2.2 AA 不是附加项，是验收项。

## 三、设计 Tokens

### 3.1 色彩

- **五色板体系**（与 Web 端 ThemePicker 对齐）：5 套可切换主题色板，每套含 light/dark 双变体；默认第 1 套浅色。
- 每套色板角色固定：`bg / surface / border / text / text-secondary / accent / accent-soft / success / warning / danger`。
- 🔒 **内容用色 ≤5 种**：单屏内非中性色不超过 5 个（含 accent）。
- 对比度：正文 ≥4.5:1，大字号/图标 ≥3:1（WCAG AA）。
- 实现：CSS 变量 → NativeWind theme 映射；禁止裸写 hex（见开发规范禁令）。

### 3.2 间距（4pt 网格）

`space-1=4 / 2=8 / 3=12 / 4=16 / 5=20 / 6=24 / 8=32 / 10=40 / 12=48`
- 页面左右安全边距 16（平板 24）；卡片内边距 16；列表项纵向间距 12。
- 交互目标间距 ≥8。

### 3.3 字阶

| Token | 字号/行高 | 用途 |
|---|---|---|
| display | 32/40 | 空状态大标题、落地页 |
| title | 24/32 | 页头标题（字距 -0.02em） |
| heading | 18/26 | 卡片/分区标题 |
| body | 16/24 | 正文（默认） |
| caption | 13/18 | 辅助说明、元数据 |
| mono | 14/20 | 提示词/参数等宽展示 |

- 字体：iOS 用系统 SF，Android 用系统 Roboto；提示词区可用等宽。
- 支持 Dynamic Type / 系统字体缩放，放大 130% 不截断关键操作。

### 3.4 圆角与阴影

- 圆角：`sm=6 / md=10 / lg=16 / xl=24 / full`；卡片 lg，按钮 md-full，媒体舞台 lg。
- 阴影（浅色主题仅细腻浮起）：`lift = y2/blur12/alpha0.06`、`float = y6/blur24/alpha0.10`；深色主题以边框替代阴影。
- 层级顺序：内容 > 浮层 > 导航；任何元素不得遮挡作品内容本身。

## 四、组件规范

### 4.1 通用规则

- 每个交互组件必有 **default / pressed / disabled / loading** 四态；pressed 反馈 ≤120ms。
- 触碰热区 ≥48×48（视觉元素可更小，热区补足）。
- 图标一律 `<Icon name="..." />`（lucide-react-native 封装），描边 1.5-2，尺寸 20/24 两档。

### 4.2 核心组件表

| 组件 | 规格要点 |
|---|---|
| Button | 高 48（主）/40（次）；主按钮 accent 实心、次按钮描边、危险操作 danger + 二次确认；loading 转圈禁重复提交 |
| PromptBar | 贴底悬浮（shadow-float + lg 圆角）；多行自适应 1-6 行；右侧发送按钮常驻拇指区；聚焦时附件/参数入口展开 |
| ParamSheet | 底部抽屉：拖拽柄 36×4 居中，下拉 30-40% 高度或快速甩动即关闭；模型/比例/数量前置，高级参数分组折叠 |
| JobCard | 作业卡片：缩略占位 → 进度环/百分比 → 完成渐显；失败态含「重试 / 修改参数」双动作 |
| MediaStage | 作品全屏舞台：双击点赞/缩放、左右滑切换、上滑看参数；图片渐进加载，视频 autoplay 静音可控 |
| GalleryGrid | 双列等宽网格（瀑布流仅作品库）；1:1 缩略；长按照出快捷菜单（下载/分享/再创作/删除） |
| TabBar | 4 项上限：创作 / 作业 / 作品库 / 我的；图标+文字，激活态 accent + 轻触 haptic |
| Toast | 顶部 2s 自动消失；成功 success / 失败 danger；不打断操作 |
| Empty | 径向微光晕锚点 + display 大标题 + 一个主动作按钮（对齐 Web 空状态语言） |
| Skeleton | 骨架屏呼吸微光（1200ms 循环），替代一切白屏转圈 |
| Dialog | 标题 + 简述 + 双按钮；危险确认主按钮在左（防误触习惯位），与平台 destructive 惯例一致 |

## 五、交互模式

### 5.1 手势表（标准手势只做标准事）

| 手势 | 用途 | 备注 |
|---|---|---|
| 点按 | 默认激活 | 一切功能的可见主入口 |
| 下拉刷新 | 列表/画廊刷新 | 所有可滚动列表必备 |
| 水平滑动 | 作品切换、轮播 | 禁止绑定破坏性操作 |
| 长按 | 快捷菜单/多选 | 仅作增强捷径，关键功能不得只藏长按 |
| 拖拽关闭 | 底部抽屉/全屏媒体 | 带拖拽柄与速度阈值 |
| 捏合缩放 | 仅作品媒体 | UI 元素不响应捏合 |

### 5.2 触觉反馈（expo-haptics）

- 确认完成（生成提交成功）→ notification success；切换开关/选项 → light impact；表单失败 → notification error；选择器滚动 → selection。
- 只在「重要时刻」使用，不为每个微交互配音效。

### 5.3 异步生成 UX（核心状态机）

```
提交 → 乐观 JobCard(queued) → 轮询(running, 进度%) → done(渐显作品) / failed(原因+重试)
        ↘ 应用退后台 → 完成时本地推送通知，回前台立即拉取终态
```

- 提交即反馈 ≤200ms；禁止「无响应等待」。
- 失败文案给**可执行下一步**（重试/改参数/查网络），不只报错。
- 弱网/离线：列表给缓存快照 + 离线横幅；生成提交排队待网恢复自动重发。

### 5.4 空状态与错误恢复

- 空状态 = 光晕锚点 + 一句话价值主张 + 主 CTA（如「开始第一次创作」）。
- 错误页三要素：发生了什么 → 为什么（一句人话）→ 现在能做什么（按钮）。

## 六、视觉风格

- **气质**：Film Atelier——暗房/剪辑台的工作台隐喻；浅色纸感底、细腻分隔线、作品微浮于舞台。
- **图标**：Lucide 线性单风格，描边统一；禁止混用填充图标、emoji、彩色图标。
- **图像处理**：作品圆角 lg + shadow-lift；画廊等宽网格保证**视觉对称**；封面裁切居中保主体。
- **配色纪律**：单屏非中性色 ≤5；高饱和色只允许出现在 accent 与状态色；禁止大面积渐变闪烁。
- **文案语气**：中文为主，简短、动作导向（「生成」而非「点击此处开始生成」）。

## 七、响应式设计标准

### 7.1 断点

| 档位 | 宽度 | 布局策略 |
|---|---|---|
| phone | ≤430pt | 单列；底部 Tab + 贴底 PromptBar |
| phone-lg / fold 展开 | 431-767pt | 单列加宽；画廊可 3 列 |
| tablet | ≥768pt | 双栏：左导航栏 + 右内容；画廊 3-4 列；ParamSheet 变右侧栏 |

### 7.2 适配规则

- **安全区**：全部内容避开刘海/Dynamic Island/系统手势区；贴底元素垫 `safe-area-inset-bottom`。
- **横竖屏**：手机竖屏优先；横屏仅媒体舞台/视频播放做专门布局，其余页面可锁定竖屏；平板双方向全适配。
- **折叠屏**：展开态按 tablet 档处理，铰链区不放置交互元素。
- **字体缩放**：系统字号放大至 130% 布局不崩、主操作可见可点。
- 断点实现：`useBreakpoint` Hook（对齐 Web 同名思路）+ NativeWind 响应式前缀。

## 八、可访问性（WCAG 2.2 AA 验收线）

- 对比度：正文 ≥4.5:1、大文本/图标 ≥3:1；五套色板每套都须过检。
- 所有图标按钮带 `accessibilityLabel`；作业进度对读屏可读（`accessibilityLiveRegion`）。
- 动效尊重系统「减弱动态效果」：开启后呼吸/渐显降级为直接呈现。
- 触碰目标 ≥48 且间距 ≥8；表单错误同时用颜色 + 图标 + 文字三通道表达。

## 九、动效规范

| 场景 | 时长 | 缓动 |
|---|---|---|
| 按压反馈 | ≤120ms | ease-out |
| 控件态切换 | 150-200ms | standard（缓入缓出） |
| 页面/抽屉转场 | 200-300ms | decelerate（物理回弹，阻尼自然） |
| 骨架呼吸 | 1200ms 循环 | 线性微光 |
| 作品完成渐显 | 300ms | ease-out + 1.02→1 缩放 |

- 实现仅走 Reanimated（UI 线程 60fps）；一切动效需有 reduced-motion 降级。
- 🔒 禁令：高饱和彩虹粒子、大面积闪光、粒子爆炸、快速频闪、粒子遮字、无层次堆叠、无景深——一律不准入库。
