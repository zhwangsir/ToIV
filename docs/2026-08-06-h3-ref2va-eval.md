## 二、评测矩阵与结果(1344×768,124 帧,24fps,20 steps,beta 调度器,seed 42)

| 组 | 参考输入 | 场景指令 | 耗时 | 结果 |

**显存峰值(逐卡 MiB)**:各组 GPU0 58,319–63,919 / GPU1 67,619 / GPU2 5,277 / GPU3 57,864——远低于第一轮 I2V 的 97.2G 红线,与生产服务共卡无压力。

## 三、关键结论

1. **身份锁定能力极强**。五组输出中角色的衣着、体型、发型、道具(菜篮/青菜)全程一致;3 参考组连场景文字细节(门牌 "602")都保真,1 参考组则幻觉成 "617"——**多参考显著提升细节准确度**。
2. **参考图即场景锚点**。参考图携带的场景信息会一并锁定:隐式场景指令(prompt 只描述新场景)三组全部锁死在原楼道;**显式「场景切换」指令才能解锁**(A3/A4 均成功迁移厨房)。
3. **prompt 工程要点**:迁移场景必须显式声明「切换到与参考图背景不同的新场景」;单角色镜头建议加「画面中只有一个女人」约束(A3 无约束时输出双角色,A4 加约束后单角色)。
4. **`match` vs `max` 档**:同 seed 下画面逐帧级相似,且 max 未更慢(222s vs 282s,后者实为冷启动);官方标称「max 慢数倍」在 1344×768 单参考规模下未体现。**生产默认 match 即可**。
5. **速度**:热态 222–292s/5s 镜,与 fl2va i2v 热启动(209.9s)同量级;肖像 t2v(56 帧)141s。
6. **音频**:各组产物均含 32kHz 立体声音轨(A4 1.5MB vs A1 768KB,音轨内容丰富度更高);台词清晰度/口型同步未做人工听审(遗留)。

## 四、与 fl2va i2v(首尾帧)路线对比

| 维度 | fl2va i2v(第一轮) | ref2va(本轮) |
|---|---|---|
| 一致性机制 | 首帧像素锚定,逐镜外链(需前镜出图) | 参考图 token 全程锚定,任意镜独立生成 |
| 跨场景 | 天然支持(首帧即新场景) | 需显式场景切换指令 |
| 角色卡复用 | 不可(依赖前镜产物) | **可**(干净肖像任意复用) |
| 多角色 | 未测 | 参考 ≤9 图/3 视频/3 音频,标签化引用(`<Picture N>`) |
| 速度 | 热 210s | 热 222–292s(相当) |

**定位互补而非替代**:i2v 适合剧情连续镜头(首尾帧衔接),ref2va 适合「角色卡 → 任意分镜」的短剧生产模式。

## 五、生产接入建议(对 Studio 模块)

1. **角色卡资产规范**:角色参考图用**干净正面肖像/半身照**(A4 验证可行),避免带场景信息的剧照作角色卡(会锁死场景,A1/A2/B1 教训)。
2. **prompt 模板**:分镜 prompt 前置「场景切换到与参考图背景完全不同的新场景,画面中只有 N 个角色」+ `<Picture N>` 按角色卡顺序引用。
3. **多参考**:主角建议 2–3 张(正面/侧面/半身),细节保真度显著优于单图(门牌号对照实验)。
4. **档位**:默认 `match`;`max` 在本分辨率无收益。
5. **优先级**:ref2va 与 i2v 并列作为 Studio 分镜引擎候选;ref2va 解决角色一致性(原 PuLID-Flux 首帧路线的上位替代——免首帧生成、免像素锚定外链)。
6. **合规**:接入前过 MiniMax H3 Community License 条款。
