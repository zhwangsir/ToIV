## 四、优化方案(按 ROI 排序,✅=本次已落地/验证)

1. **H3 长片热管理标准件(✅ 已验证,待固化为集群默认)**:风扇曲线懒惰是根因(400W 负载风扇 37%)。
   处方:NVML 锁扇 85% + 功率帽 450W(GPU2)。建议:做成 systemd  unit 或 toiv-comfyui-h3 的
   ExecStartPre(夏季模式),并写回 AGENTS.md 易错点;长期仍应改善机箱风道(易错点 20 结构性风险)。
2. **t2v 镜 prompt 必须显式约束人数与角色(✅ 已验证)**:负向不进 H3 节点,任何"不要"必须写进正向
   ("only two people…, no crowd, no bystanders");凡画面可能出人的镜,要么带角色块要么显式 "no people"。
   建议:剧本拆解/润色层把该规则写进 prompt 模板(与 dogfood 遗留 #1 真人范式切换同点修复)。
3. **drama 链路 i2v 一等公民化(本次绕行方案已验证)**:generate-video-v2 仅 t2v;本次 i2v 经
   /api/h3/i2v + psql 手工写回 dramashot(UPDATE video_url/video_status)。建议:v2 请求加
   `image_url` 透传(H3VideoGenerator.supports_image2video=True + build_h3_i2v_graph),
   写回复用现有 _await_shot_video_writeback;角色卡 reference_front 直接可选为首帧。
4. **SenseVoice /analyze 作台词 QA 标准件(✅ 已验证)**:台词镜落成后自动跑一次,文本比对
   shot.dialogue + 情绪/事件标注,不达标重提或转 /lipsync。成本 ~2s/镜,可编进 tracker 写回钩子。
5. **whisper.cpp(studio02 :9212)转写空应答(待修)**:/health 200 但 /v1/audio/transcriptions
    curl 52 empty reply(wav/mp3 均复现),疑崩溃;排查 launchd 日志。ASR 主链路目前靠它。
6. **熔断恢复精确化(编排器已修,平台侧借鉴)**:clear pending 后 running 镜不得重提(否则重复烧 7min);
   启动恢复须 queue/history 双查再 requeue。drama 平台侧 reconcile 可复用此对账逻辑。
7. **H3 自发字幕与 assemble 字幕互斥(沿用上轮建议 #4)**:本次成片台词字幕全部 H3 自烧,assemble
   传 title="" 零二次烧录,验证通过;建议 assemble 增加 burn_subtitles 开关(默认关 for H3 链)。
8. **超分脚本画幅方向护栏(✅ 已落地)**:video_4k_upscale_parallel.py 默认 3840×2160 横屏目标,
   竖屏源必须显式 `--target-w 2160 --target-h 3840 --keep-frames`;已加源/目标横竖一致性硬校验,
   防重复 97min 报废(AGENTS.md 易错点 28)。

## 五、结论

H3 可独立交付 **5 分钟竖屏真人仙侠短剧**:竖屏规格、i2v 锁脸一致性、台词口型(中文念白+自烧字幕+
情绪配乐)、长片连续生产(450W+85% 扇稳态 ~6min/镜)全部真机实证。25 镜首轮 25/25 成功,
QA 逮出 2 镜幻视缺陷并经 prompt 约束重做修复。剩余工程化空间集中在 i2v 一等公民化、
prompt 模板的人数/角色硬约束、以及热管理标准件固化。
