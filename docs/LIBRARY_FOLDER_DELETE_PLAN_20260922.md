## 二、删除语义边界（逐类核实，方案的红线）

1. **变体/360 组是前端派生**（`libraryQuery.ts:413-470`）：组只存在于当前筛选+分页视图——**删除必须在点击瞬间快照成员 id 列表**，不能删「组」这个抽象（视图外成员不动）。
2. **运行中/排队成员**：现单件删除无状态闸（running 也照删，软删后 tracker 仍可能回写）。整组删除必须**跳过非终态成员**（或在 Modal 明示「N 件进行中将被排除」）。
3. **画板成员**：被删作品在板内**静默跳过不炸板**（`boards.py:246` 软删同样跳过）——语义可接受，确认文案提示即可。
4. **版本树/续写链**：删父作留子作 dangling（parent_id/continued_from 指向已删作业）——灯箱「续写于」跳转落空，前端已有 404 容忍；不做级联删（子作是独立作品）。
5. **链式作业段**（keyframe_chain/extend 的 params.segment ids）：只用于取消传播，**删除不传播**（各段独立）。
6. **撤销**：现有 undo 是 per-job token；批量流已有「全部撤销」循环（`LibraryView.tsx:924-937`）直接复用。
7. **R18**：本 admin 无 nsfw_enabled，列表本就不含 R18；组删除只作用于可见成员，天然安全。
8. **Saved Views**：删除语义=删视图定义（localStorage+云端偏好），与作品删除严格分离。

## 三、方案

### P0 文件夹整组删除（核心；纯前端可成，零 API 变更）

- **入口**：文件夹卡加 hover 操作组（与普通卡同族）：「打开」「删除整组」；批量管理模式下文件夹卡可选中（选中=全部终态成员入删单，计数气泡明示）。
- **确认 Modal**：成员数 N + 状态分布（done X/error Y）+「进行中 M 件将被排除」+「进入回收站 72 小时可恢复；画板中的成员将静默移除」+ 沿用「不再确认」偏好。
- **执行**：复用 `deleteJobsBatch(成员 ids)`（顺序单删+失败不中断）→ toast「已删除 N 个作品·全部撤销」→ 成员 <2 文件夹自然消失（既有回落逻辑）。
- **测试**：更新三处「不做整组删除」注释；`libraryBatch.test.ts` 保留「<2 回落」不变式、改形态断言；新增文件夹删除入口/确认流/撤销/进行中排除四组 jest；e2e 补一例（authed-library-p0.spec.ts 模式：造变体组→整组删→撤销还原）。

### P1 服务端批量端点 + 删除面补齐

- `POST /api/jobs/bulk-delete`（ids≤200；逐件归属校验+软删+per-job 审计与 undo_token（复用现有撤销/回收站语义）；返回 done/failed 分组；**POST 静态段无路由冲突**——`DELETE /jobs/{job_id}` 吞静态段坑已绕开）。
  - 价值：大组（>20 成员）一次 HTTP 完成，避免 N×frp 往返；前端 N>20 自动切端点，小组仍走本地循环。
- Saved Views chips 加 ×（独立小确认，文案「仅删除视图，不删作品」）。
- 板列表卡补「删除画板」入口（现仅详情页可删）+ `boards.py:208` 补 `audit.record`（与 Job 删除审计范式对齐）。

### P2 卫生项

- 变体分组排除系统 kind（`app_cover_demo`/`app_cover`）——admin all=1 视图不再出 209 成员伪文件夹。
- 回收站批量恢复（trash 视图多选 restore，循环现有端点即可）。
