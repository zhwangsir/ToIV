## 〇、摘要（核心结论）

1. **「liblibTV」作为独立产品名未找到公开信息**；用户所指的学习对象实为 **LiblibAI（哩布哩布 AI）**——国内最大的 Stable Diffusion 生态平台，已从「模型社区」演进为「图片+视频+LoRA 训练+工作流市场」的一站式创作平台，并在其视频/内容分区中设有「短剧漫剧」类目。它对 ToIV 的最大启示不是某个单点功能，而是**「资产库（模型/角色）+ 工作流复用 + 创作者生态」的平台化打法**。
2. **AI 短剧市场已进入爆发期**：2024 年中国微短剧市场规模 504.4 亿元（首超电影票房），2025 年 AI 真人短剧供给增长 76 倍、播放量超 700 亿、规模约 189.8 亿元；抖音（即梦）与快手（可灵）双寡头以保底扶持+流量分账激烈赛马。
3. **行业公认最大技术痛点是「主体一致性」与「对口型」**——这正是 ToIV 技术栈（FLUX 参考图关键帧 → i2v 视频）的主攻方向，也是产品差异化机会所在。
4. **一站式流水线（剧本→分镜→关键帧→视频→配音→成片）已成为头部产品标配**（昆仑万维 SkyReels、白日梦 AI、有戏 AI 等均如此），ToIV 应把「分镜级流水线 + 角色库」作为 P0 核心。
5. ToIV 已有 ffmpeg 合成与播放器埋点，建议将埋点数据回流用于**分集流失分析 → 反哺剧本节奏优化**，形成「生成-分发-数据-优化」闭环，这是纯生成工具（liblib/白日梦）没有的差异化优势。

### 1.4 从提示词到成片：LiblibAI 的短剧/视频工作流拆解

综合公开信息，其视频/短剧路径为**「两段式」**：

1. **资产段**：模型库选底模/LoRA（或自行训练角色 LoRA）→ 在线生图（文生图/图生图 + ControlNet）产出关键帧；
2. **生成段**：视频生成器选择聚合模型（如 Seedance 2.0 参考生视频 / 可灵 3.0）图生视频 → 配音/BGM（轻量路径走「文本生成视频」内置语音角色）→ 导出。

值得注意的设计细节：
- **「做同款」按钮**：社区作品可一键复用其模型+参数组合，把「高手配置」平民化；
- **模型路由而非自研**：视频层聚合第三方 SOTA 模型，用户按效果/价格自选，平台赚算力差价；
- **WebUI/ComfyUI 双模式**：新手用表单式 WebUI，专业用户用节点式 ComfyUI，兼顾低门槛与高自由度。

**未找到公开信息**：LiblibAI 是否提供「剧本 → 自动分镜 → 批量镜头」的整剧级流水线（其视频能力目前偏单镜头/轻量成片，整剧编排能力未见公开披露）。

### 2.4 行业的冷思考（机会与风险）

雪豹财经社调研揭示的现实痛点（直接决定产品该做什么）：

1. **主体一致性是最大技术难题**——「文生图-图生视频」链路中人物难以保持一致，对口型常穿帮，环境/道具也会漂移；「目前没有任何一个模型和工具能够彻底解决这个问题」。
2. **「PPT 式短剧」与「面瘫演员」**——镜头不流畅、节奏奇怪、光发声不动嘴，剧情全靠后期配音推。
3. **良率低、靠抽卡**——一个镜头常需生成二三十次才有勉强过关的，需要专人画分镜（数百张）。
4. **镜头语言缺失**——推拉摇移、场景切换、节奏呈现无法用 AI 简单替代。
5. **工具迭代过快**——作品未上线即过时，小团队疲于学习新功能。
6. **商业分层**——2–3 分钟精良 AI 短片已可行；100 分钟有故事线的整剧仍达不到标准；跑通商业化的多为大型影视公司（博纳 AIGMS、华策 AIGC 研究院）与摸到题材的头部团队。

## 四、AI 短剧生产工作流最佳实践

综合标杆案例与大量实操教程，当前行业主流管线（与 ToIV 技术栈高度同构）：

```
① 剧本（LLM 生成/人工） 
   → ② 主体资产：角色卡（多视图）、场景、道具（参考图/LoRA/主体库）
   → ③ 分镜脚本：场景/角色/台词/画面描述/景别/时长（LLM 自动拆解）
   → ④ 关键帧：文生图/参考生图（FLUX 类模型 + 角色参考注入）
   → ⑤ 镜头视频：图生视频 i2v 为主，首尾帧控制（t2v 仅用于空镜/大场面）
   → ⑥ 配音：TTS 情感控制 / 声音克隆，逐分镜对齐台词
   → ⑦ 对口型：lipsync（观众对"面瘫不动嘴"零容忍）
   → ⑧ 后期：剪辑拼接 + 字幕 + BGM + 混音（剪映/ffmpeg）
   → ⑨ 分发与数据：平台分账/投流，播放数据反哺创作
```

各环节要点（均有来源支撑）：

1. **剧本与分镜**：LLM 生成剧本后需「分镜增强」——白日梦 AI 的「剧本增强」模式建议一次生成 3 版选反转最强的；专业团队会配专人画数百张分镜。[头条-白日梦教程](http://m.toutiao.com/group/7488925740856082959/)、[雪豹](http://m.toutiao.com/group/7506013481003516428/)
2. **角色一致性（核心战役）**：行业共识方案是「**角色卡 + 角色库**」——先固定主角多视图（正面/侧面/特写），所有分镜强制引用同一角色资产；进阶方案为角色 LoRA 训练（LiblibAI 15 分钟云端炼丹）与多主体参考（Vidu 主体库、可灵 Omni、Seedance 2.0 全能参考）。[头条-分镜教程](http://m.toutiao.com/group/7587155540954923571/)、[头条-有戏 AI](http://m.toutiao.com/group/7659322264831164974/)
3. **i2v vs t2v 取舍**：主体镜头一律走「关键帧 → i2v」（可控性优先）；t2v 仅用于无角色的空镜与大场面。即梦智能多帧证明「多关键帧串长镜头」可减少跳切、提升连贯性。[chinaz](https://www.chinaz.com/ainews/20745.shtml)
4. **良率管理（抽卡机制）**：单个镜头平均生成 20–30 次才可用 → 产品必须内置**单镜头多候选批量生成 + 快速挑选/收藏**机制，否则人工成本吞噬 AI 红利。[雪豹](http://m.toutiao.com/group/7506013481003516428/)
5. **配音与口型**：声音克隆（IndexTTS 系列本地离线可用、DubbingX 等）+ 逐分镜台词配音 + 自动对口型是一站式工具标配（有戏 AI：每个分镜单独输入台词、选音色、自动对口型）。「说台词不动嘴」是观众首要槽点。[头条-有戏 AI](http://m.toutiao.com/group/7623367801603883554/)、[雪豹](http://m.toutiao.com/group/7506013481003516428/)、[淘宝-IndexTTS](https://tvgame.taobao.com/topic/aiyouxi_256/353fc2f667f9a2fbcccc41f453a10ce0.html)
6. **后期与分发**：剪映/剪辑合成 → 平台分发（抖音/快手保底+分账）→ 数据复盘；注意观众习惯 1.5 倍速观看、重台词与剧情推进而非视觉效果 → **节奏与爽点密度优先于画质**。[雪豹](http://m.toutiao.com/group/7506013481003516428/)
7. **题材选择**：优先奇幻/玄幻/民俗悬疑/科幻（AI 友好），规避强真人情感戏。[雪豹](http://m.toutiao.com/group/7506013481003516428/)

## 五、对 ToIV 的功能启示（按优先级）

> ToIV 现状：本地部署管线（FLUX 关键帧 + LTX 视频 + IndexTTS2 配音 + ffmpeg 合成 + Web 播放器埋点）。以下建议按 P0（必须先做）/P1（增强竞争力）/P2（长期生态）排序。

### P0 —— 短剧管线的「骨架」

| # | 功能 | 说明与理由 |
|---|---|---|
| P0-1 | **剧本 → 分镜自动拆解** | 输入剧本（或一句话题材），LLM 输出结构化分镜脚本（场景/角色/台词/画面提示词/景别/时长），作为整条管线的数据骨架。这是一站式产品（SkyReels、白日梦、有戏 AI）的共同入口，没有它 ToIV 只是单镜头工具。 |
| P0-2 | **角色库 / 角色一致性管理** | 角色卡 = 名称 + 多视图参考图 + 风格描述 + （可选）角色 LoRA；分镜生成关键帧时强制绑定角色资产，FLUX 侧走参考图注入/IP-Adapter 类方案。主体一致性是行业公认最大痛点（雪豹调研），也是 ToIV 选择 FLUX→i2v 路线的立身之本，必须产品化而非散落在提示词里。 |
| P0-3 | **分镜级流水线状态机** | 每个分镜独立跟踪「关键帧 → 视频 → 配音 → 口型 → 完成」状态，支持单环节重生成而不影响其他环节；对应「抽卡 20–30 次」现实，需支持**单镜头批量生成多候选 + 一键选定**。这是把「59 分 PPT 短剧」提到及格线以上的工程基础。 |
| P0-4 | **一键合成成片（ffmpeg 模板化后期）** | 在现有 ffmpeg 能力上扩展：分镜自动排序拼接 + 字幕烧录（来自分镜台词）+ BGM 轨道 + 音量归一/混音 + 分集导出（竖屏 9:16 优先）。对标白日梦「20 分钟成片」体验。 |

### P1 —— 体验与差异化

| # | 功能 | 说明与理由 |
|---|---|---|
| P1-1 | **配音情感控制与对口型（lipsync）** | IndexTTS2 已具备情感/克隆能力，需将其参数（情感、语速、音色）暴露到分镜级 UI，并接入对口型环节。「光发声不动嘴」是观众首要槽点，此项直接决定作品能否被当成「短剧」而非「配音秀」。 |
| P1-2 | **短剧题材模板库** | 内置验证过的题材模板（民俗诡事、战神、赘婿、甜宠、穿越、玄幻大场面），每套模板含：剧本结构（爽点节奏）、分镜范式、角色设定、风格提示词、BGM 风格。对应 LiblibAI 内容分区与「做同款」机制的本地化版本。 |
| P1-3 | **播放器埋点 → 创作反哺闭环** | ToIV 独有资产。把分集完播率、流失点、倍速行为回流到作品维度，输出「第 N 集 M 秒流失」报告，指导分镜节奏与爽点密度调整（观众 1.5 倍速观看、重剧情推进的行业事实）。这是 liblib/白日梦等纯生成工具不具备的闭环。 |
| P1-4 | **分集与剧集管理** | 短剧以「集」为单位分发（参考《三星堆》12 集日更、《兴安岭诡事》11 集），需要剧集 → 分集 → 分镜三级模型，支持分集独立生成/重制与批量导出。 |

### P2 —— 生态与长线

| # | 功能 | 说明与理由 |
|---|---|---|
| P2-1 | **工作流/模板导入导出与分享** | 借鉴 LiblibAI 工作流市场「一键复制高手方案」：把「剧本模板 + 角色包 + 提示词包 + 后期配置」打包为可分享的短剧工程模板，为未来的社区/团队协作者做准备。 |
| P2-2 | **内容安全与合规层** | LiblibAI 被央视点名的教训：即使本地部署，也应内置提示词/输出审核开关与合规提示，防止滥用连带风险（尤其 ToIV 已有 nsfw 相关规划文档，更需明确边界）。 |
| P2-3 | **多语言配音与出海支持** | 昆仑万维、中文在线、阅文等集体押注 AI 短剧出海；IndexTTS2 多音色/多语言能力配合字幕多语言化，可作为长线卖点。 |
| P2-4 | **成本与速度看板** | 行业核心卖点是「成本仅实拍两三成」；为本地管线记录每集算力耗时/显存/失败率，帮助用户量化 ROI，也便于内部优化 LTX/FLUX 调度。 |
