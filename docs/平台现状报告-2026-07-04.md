## 四、能力实况

### ✅ 已端到端验证（本轮实测通过）

- **出图全链路** —— FLUX.2 dev 真机出图，成片经代理取回（206 · 落 NAS）
- **生成内容 → NAS** —— 译制 / 漫剧 / forge / cad 产物落 NAS（cifs 挂载），并经 SFTP 独立确认
- **模型下载 → NAS** —— Civitai / HuggingFace 服务端解析下载链，A 期 3 个模型 ~59GB 实测下载
- **作品库** —— 48 件正常渲染，视频加 HTTP Range 后可播 / 可拖动，标签友好
- **NSFW 隔离** —— 主站彻底零 R18，仅 `/nsfw` 可见（X-NSFW header 门控）
- **分镜并发** —— 受控并发 + 参考图分发全 pool，带角色参考图的镜也能跨机真并行
- **转视频修复** —— 能力过滤新增「必需节点」校验，缺 VHS 的 PC01 被排除出视频路由

### ⚠️ 未完成 / 已知局限

- **动漫对口型** —— 做不了。LatentSync 训练于真人脸；自建 v0 为音频驱动的合成口腔（糙、非逐音素唇形）。真·动漫唇形是**研究级难题**。
- **真人对口型** —— seed bug 已修（此前 100% 失败的根因），但 worker 侧 `temp WinError`（.100 Windows 临时文件权限）未解，**尚未用真人片实测主观质量**。
- **日韩配音** —— 未部署。IndexTTS2 仅支持中英，日韩需另部署跨语种 TTS。
- **B 期评估层** —— ImageReward 打分 + Best-of-N（多出优选）未做，卡在需手动在 .100 安装 ImageReward。
- **创意质量** —— 对口型 / 克隆音色 / AI 精剪的**机械链路**已证，但**主观质量**仍待真实素材 + 人工判断。
- **公网上传** —— spark02↔云物理链路 ~17KB/s，大文件上传慢；**走 LAN 地址秒传**。
- **FLUX.2 dev** —— 33GB，首次载模型 ~2.5 分钟，更吃显存（之后快）。
- **画布默认底模** —— 图片节点默认仍是 Klein，未跟全局默认（dev）同步（可下拉手选；小瑕疵）。

## 五、风险与运维注意

| 类别 | 说明 |
|---|---|
| **数据** | 内存态后台作业（模型下载、对口型、配音轨）在 **api 容器重启**时丢失；下载无断点续传，断了重下即可。 |
| **基建** | 公网↔spark02 物理链路 ~17KB/s 是硬伤（路由 / 带宽层面），软件层绕不开；内部使用走 LAN 无此问题。 |
| **存储** | 数据库（SQLite）与 RAG 缓存**刻意**留本地卷（网络盘慢 + 易损）；仅模型与生成内容上 NAS。 |
| **部署** | 部署脚本只同步 `apps/`，不同步 `deploy/`（compose / .env）；改基建配置需手动同步 spark02。 |
| **凭据** | NAS / Civitai 等密钥走 `deploy/.env`（rsync 排除，不入仓库）；请勿硬编码进代码。 |
