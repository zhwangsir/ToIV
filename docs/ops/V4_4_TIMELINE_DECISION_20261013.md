## 1. 判据复核（生产数据 2026-10-13）

| 证据 | 数据 |
|---|---|

| Agent 代操 | `render_video_edit`/`rough_cut_video` 工具已在位（V4-1），LLM 可直接操作时间线 JSON |

## 2. 决策

**真时间线（拖拽编辑器/Remotion/时间线 DSL）显式后置**，理由：

1. **需求侧**：自用平台的成片路线是「逐镜生成 → v2 时间线编排（排序/时长/衔接策略/字幕）→ splice2 拼接」，三轨微调属偶发（数据：零使用）。
2. **技术侧**：ShortGPT EML 的真实价值是「LLM 可操作时间线」——V4-1 已用 `render_video_edit` 工具达成同等能力（LLM 直接产 plan JSON），专门 DSL 的边际收益趋零。
3. **成本侧**：拖拽时间线编辑器是 2-3 批级前端工程 + 长期维护面，与「本地自用」定位不匹配。

## 3. 后置触发条件（满足任一即重新评估）

- 实际创作中出现 ≥3 次「v2 时间线/表单式剪辑无法表达」的剪辑需求（如多段内嵌转场、画中画、关键帧动画）；
- Agent 代操发现 plan JSON 表达力不足（LLM 频繁无法表达用户剪辑意图）；
- 决定对外发布产品（多用户内容生产场景）。

## 4. 现状保持

- `/toiv/video-tools`（表单式三轨）保留，作为 Agent `render_video_edit` 的 UI 对应面；
- v2 时间线段（排序/时长/seam/字幕）维持主路径不变；
- Remotion/拖拽编辑器不再出现在活跃计划中（本节即归档位）。
