### 1.2 核心用户流程(现状)

- **生成主路径**:灵动岛选 image/video → 全出血舞台(空态三步引导)→ 底部 PromptBar 输入 → OptimizeButton 优化(联动负向提示词)→ 生成 → ResultPanel 选中大图 + 胶片条 + A/B 对比。这条路径是 v5 重构过的,**是当前全站体验最好的流程**。
- **作品消费路径**:library 筛选 tab → masonry 网格 → hover 快捷操作 → 存为风格卡(StyleBar)→ 回流到生成优化管线。闭环已通,但筛选映射有 bug。
- **工具路径**(编辑/分镜/译制/数字人):藏在「更多」抽屉,发现性差;每个工具是独立表单页,互相不联动。
- **登录**:单卡片 email/password,无注册/找回/错误细化。

### 1.3 当前 UI 风格总评

- **风格**:曜石熔岩 v5——暖黑底(`#0A0908` 系)+ 单一熔岩橙 accent(`#FF6B2C`)+ Liquid Glass 浮层 + 2% 噪点纹理。方向正确且有辨识度。
- **布局**:桌面顶部居中灵动岛(玻璃胶囊,悬停展开标签)+ 视图区;移动端底部 5 项导航 + 更多抽屉。生成三视图是「舞台 + 右侧玻璃参数浮板 + 底部悬浮 PromptBar」的剧场版型。
- **字体**:Inter / JetBrains Mono 已注入;Fraunces(display 衬线)仅剩 ManjuView 两处在用。
- **token**:`globals.css:11-141` 定义完备(色阶/玻璃/排版五档/4px 间距十档/圆角/阴影七档/动效/z-index/断点),硬编码 hex 近乎为零,token 执行度好。

### 1.4 主要问题清单(按严重度)

**A. 架构级(决定"要不要推倒"的问题)**

1. **双生成 UI 体系并存**:v5 剧场化 GenerateView(553 行,引擎注册表数据驱动)与 NSFW 的 CreateView(1876 行)+ NsfwVideoView(1656 行)旧表单体系是两套并行世界。NSFW 没有吃到 v5 任何红利:无舞台、无 PromptBar、无玻璃浮板、无负向联动(负向联动是本次刚补的,但交互壳仍是旧的)。OptimizeButton 注释自述曾跨 6 视图复制。
2. **FROZEN 巨型视图连环**:DramaStudioView(3411 行)+ ManjuView(2670 行)已退役却仍被 animatic 桌面端依赖(`page.tsx:425-440`),拖着整块 legacy token 别名(`globals.css:143-180`)和 Fraunces 字体无法删除。6081 行死重量卡在设计系统咽喉上。
3. **样式策略三分天下**:styled-jsx(35 文件 44 块)/ 全局 CSS / CSS Module 并存;`library.css` 要靠前缀特异度**压过**组件内旧 styled-jsx;`globals.css` 混入 `.anim-*`/`.avatartalk-main`/`.video-submit` 等视图专属样式,全局与局部的边界已经失守。
4. **通用组件覆盖率低**:`components/ui/` 14 个组件,Icon(48 引用)/Toast(16)/Input(10)/Button(7)尚可,但 **Modal/Empty/Skeleton/ErrorBoundary 各仅 1 处引用**——各视图在 styled-jsx 里自写按钮、卡片、空态,重复量大,改一处设计要改 N 个文件。

**B. 一致性与 polish**

5. 断点取值混乱:720/768/860/900/1023/1024/1025 七种并存;JS `useIsMobile` 阈值(768)与 CSS 灵动岛断点(1024)不一致。
6. 字号双轨(新五档 + 旧七档"待收敛")、圆角双轨(`--radius-panel/control/badge` + `--radius-xs~xl` 重复定义)。
7. 死 CSS 实锤:`.cv-toolbar/.cv-tb-btn/.cv-run-selected/.mode-switcher`(`globals.css:1091-1124`)全库无引用;`--topbar-h: 0px` 空变量;`components/layout/` 空目录;`.video-submit` 疑似无引用。
8. 无设置视图:账户/偏好/引擎状态散落各处,资源页承载过多。
9. 移动端破损链(audit P2 #9-13):生成视图参数面板独占首屏、studio 阶段条断字、dub 步骤条裁剪、admin 表格溢出、assistant placeholder 不适配。
10. 遗留 audit P1 项:参数浮板溢出视口(#4)、A/B 开关被浮板遮挡(#6)、fusion 右侧 456px 死空间 + badge 静态隐形(#7)、作品库筛选映射假分类 + hover 压字 + 失败卡黑墙(#8)、audio 视图布局结构崩(#5)。

**C. 视觉/体验层(用户"觉得一般"的根因)**

11. **视觉深度仍不足**:玻璃材质只覆盖了岛/浮板/PromptBar,其余视图(工具类、资源类、studio)仍是平面灰卡 + 1px 描边,同一个 App 里两种质感并存。
12. **内容主角感只做到了生成三视图**:作品库才是用户资产沉淀处,但仍是"卡片列表"思维,没有"作品即舞台"的沉浸浏览(全屏查看、键鼠穿梭)。
13. **交互反馈薄**:assistant 后端不可达时静默装死;生成错误抛底层原文(`sent 1011 keepalive ping timeout`);空态/加载态/错误态三态覆盖率低(与问题 4 互为因果)。
14. **工具模块发现性差**:imageEdit/videoEdit/animatic/dub/studio/avatartalk 全在「更多」抽屉,等于六个功能没有首页。

## 二、UI 优化目标

1. **更简洁**:一个功能只在一个地方;参数渐进披露(主参数外露、高级参数收拢);每屏一个视觉主角。
2. **更美观**:玻璃质感从"导航特权"推广为全局浮层语言;作品展示全出血化;消灭平面灰卡与玻璃并存的双质感。
3. **更统一**:单一样式策略收敛方向;断点收敛为 3 档;字号/圆角单轨;通用组件覆盖率作为验收指标。
4. **更具艺术感**:坚持"曜石熔岩/黑镜剧场"的辨识度——暖黑 + 熔岩橙 + 玻璃 + 噪点,不做第二个 Linear 复制品;作品是舞台,UI 是剧场灯光。
5. **更符合产品定位**:ToIV 是**多模态 AI 创作套件**(图/视/音/数字人/短剧),不是后台管理系统。视觉应对标 Krea、Runway、Midjourney Web,而不是 Linear/Notion。

## 三、推荐设计方向:「曜石熔岩 · 完成态」(Obsidian Lava — Final Form)

不另起炉灶。v5 的调研(Krea 内容即界面 / MJ 提示词条英雄控件 / Liquid Glass / 无限画布)结论仍然有效,问题只在**只完成了 30% 的覆盖**。本方案是把它做完全。

### 3.1 风格关键词

暖黑剧场 / 内容全出血 / 玻璃浮层 / 熔岩单点高光 / 编辑部排版 / 静音工程感

### 3.2 色彩规范(在现有 token 上收敛,不新增体系)

| 角色 | token | 值 | 使用规则 |
|---|---|---|---|
| 画布底 | `--bg-canvas` | `#0A0908` | 唯一页面底色,禁止任何纯黑/纯白面 |
| 面 1-3 | `--bg-surface-1/2/3` | 暖黑阶梯 | 静态内容只用面;浮层一律用玻璃不用面 |
| 玻璃 | `--glass-*` | blur(20px) saturate(1.4) + 高光内描边 | **一切浮在内容之上的东西**(岛/浮板/Popover/Toast/Modal/抽屉) |
| 强调 | `--accent` | `#FF6B2C` | 每屏 ≤1 个实心 accent 元素;运行态/CTA/激活专用 |
| 强调底 | `--accent-soft` | 橙 14% | badge/选中态/chip 静态可读态 |
| 状态 | ok/warn/err/run | 既有四色 | 仅状态语义,禁止装饰性使用 |
| 文字 | `--text-1/2/3` | 三档 | 对比度正文 ≥4.5:1(玻璃面上必须重扫 axe) |

红线:accent 橙不做大面积铺色、不做渐变文字;彩色阴影仅允许主 CTA 的信号光晕。

### 3.3 字体与排版(收敛为单轨五档,删旧七档)

| 档位 | 规格 | 用途 |
|---|---|---|
| Display | 28/600, -0.02em | 空态大标题/页面级标题(仅舞台类) |
| H1 | 20/700 | 页面标题 |
| H2 | 15/600 | 区块标题 |
| Body | 14/400, 行高 1.6 | 正文/表单 |
| Caption | 12/400 | 辅助/说明 |
| Label | 11/500, +0.04em 大写 | 标签/徽章/分区眉 |

- 数字与参数一律 `tabular-nums`(JetBrains Mono 仅用于 seed/参数值等"数据读数"场景)。
- 删除 Fraunces 与 `--font-display`(随 ManjuView 退役一并移除)。

### 3.4 布局系统

- **断点收敛为三档**:`≥1024` 桌面(灵动岛)/ `640-1023` 平板(底栏 + 浮板转抽屉)/ `<640` 手机。JS 与 CSS 共用同一组值(出 `useBreakpoint()` 替代 `useIsMobile`,阈值 1024/640)。
- **页面三版型**:
  - *剧场版*(生成/作品库详情/数字人):全出血内容 + 玻璃浮层,无页面滚动条;
  - *工作台版*(编辑/译制/工作室/资源):顶栏标题 + 12 栅格内容区,max-width 1200 居中;
  - *沉浸版*(canvas / drama 播放):零 chrome,全屏。
- 间距:4px 基数,面板内边距 16/20,区块间隔 24,剧场版浮层距边 16。

### 3.5 组件规范(以覆盖率验收)

- **样式策略收敛**:新/重构代码一律全局 CSS(token + BEM 前缀);styled-jsx 只出不进,随视图重构逐步清零;CSS Module 不再新增。
- **通用组件强制清单**:按钮/输入/卡片/Modal/Empty/Skeleton/Tabs/Badge/Switch/Popover/Toast **禁止视图内自写**;把目前散落的 3 种按钮写法、N 种空态收进 `ui/`。验收指标:Modal/Empty/Skeleton 引用数从 1 → 全覆盖。
- 状态五态(default/hover/active/focus/disabled)已在 v3 规范,维持执行。
- **三态覆盖率**:每个数据区块必须有 空/加载/错误 三态(消灭 assistant 静默装死类问题)。

### 3.6 图标与视觉元素

- 图标全部 lucide-react 经 `ui/Icon.tsx`,1.75px 线性,零 emoji、零彩色填充图标。
- 空态:单一插画语言——细线轮廓 + 熔岩橙单点点缀,不用第三方插画库。
- 失败占位:收敛为矮高(4:3)灰面 + 小图标 + 一行原因,杜绝"黑墙"。

### 3.7 动效原则

- 全部 ≤200ms;浮层进出场用既有 `linear()` 弹簧模拟,仅用于岛/浮板/抽屉三处。
- 列表入场 stagger ≤30ms/项;hover 仅 surface 升档或 1.02-1.03 缩放。
- 生成中:骨架 shimmer,禁 spinner 滥用;页面切换维持 View Transitions cross-fade。
- 不引入任何动画库。

## 四、关键页面优化方案

### 4.1 登录页(LandingPage)

- 现状问题:单卡片可用但平庸;注释残留"靛蓝主题";无注册/找回;错误反馈粗。
- 方案:左 60% 品牌剧场(最近一件用户作品全出血轮播 + 噪点 + 暗角,未登录则用示例作),右 40% 登录玻璃卡;错误内联到字段级;保留单字段聚焦态橙描边呼吸。改动量小,是"第一印象"性价比最高的一页。
- 判断:**保留重构**(不换结构,换质感)。

### 4.2 首页/对话(assistant,默认视图)

- 现状问题:历史会话不进侧栏、后端不可达静默装死、移动端 placeholder 不适配(P3 #14、P2 #13);空态缺少"能做什么"的引导。
- 方案:空态改"能力引导剧场"——三张玻璃卡(生成一张图 / 生成一段视频 / 让数字人开口)点击即带 prompt 预填跳转对应工作台;错误态气泡 + 重试;会话落盘或侧栏刷新;placeholder 按端出文案。
- 判断:**保留 + 体验硬化**。

### 4.3 核心生成页(GenerateView image/video/audio)

- 现状:全站最好,但有 P1 未修项——参数浮板溢出(#4)、A/B 被遮挡(#6)、audio 布局结构崩(#5)、移动端参数面板独占首屏(#9)。
- 方案:
  - 浮板 `max-height: calc(100dvh - 岛高 - 32px)` + 内部滚动;A/B 开关并入舞台左上状态胶囊行;
  - 移动端参数面板默认收成底部抽屉(handle 上拉展开),舞台永远占首屏;
  - audio:TtsCard 移出生成 tab(或改舞台内嵌浮层),还舞台完整高度;
  - 尺寸 chip 向上展开 + Esc/外点收起;生成中占位框宽高比跟随目标尺寸。
- 判断:**保留 + 按 audit 清单闭环**。

### 4.4 NSFW 生成(CreateView + NsfwVideoView)——**推倒重做**

- 现状问题:3500 行旧表单体系,与 GenerateView 双轨;无舞台/无 PromptBar/无双联动(正向+负向优化已补但壳旧);R18 模型清单折叠混杂在生成表单里。
- 方案:**不新写第三套 UI,而是让 GenerateView 吞并它**:
  - 引擎注册表增加 NSFW 引擎分级(R18 用户可见,`/nsfw` 路由保留直达并预锁引擎组);
  - 生成壳复用剧场版;NSFW 特有参数(checkpoint/采样)走引擎 schema 动态渲染(这正是 GenerateView 已有的能力);
  - R18 模型清单移到资源页 NSFW tab。
- 收益:消灭双生成体系(问题 A1),OptimizeButton 等 7 处复用点不再复制;约 -3000 行。
- 判断:**推倒重做(以合并的方式),是全方案收益最大的一项**。

### 4.5 作品库(library)

- 现状问题:筛选映射假分类、hover 压字、失败卡黑墙(P1 #8);样式双份(library.css + styled-jsx)。
- 方案:
  - kind 映射表补齐(transcribe/voice_track→音频,dub_lipsync/frame_interpolate/hunyuan→视频,未知→全部);
  - 增加**沉浸查看器**:点击作品 → 全出血灯箱(玻璃工具条:下载/存风格/复用提示词/删除),←/→ 穿梭,Esc 退出——把"舞台"从生成页延伸到消费页;
  - hover 快捷条出现时提示词文本淡出让位;失败卡矮高化;
  - styled-jsx 清零,样式单归 library.css。
- 判断:**保留重构 + 增加沉浸查看器**。

### 4.6 动态分镜 / DramaStudio / Manju——**退役替换**

- 现状问题:6081 行 FROZEN 代码被 animatic 桌面端依赖,卡住 legacy token 和 Fraunces 的删除。
- 方案:AnimaticView(547 行)升级为全端唯一实现(补桌面端分镜网格密度);DramaStudioView/ManjuView 物理删除,连带 `globals.css:143-180` legacy 别名、`--font-display`、Fraunces 字体一起清出。
- 判断:**推倒(删除)**,风险点:删除前确认 DramaStudio 内无未迁移的独特能力(走查其 3411 行的功能清单,差异项补进 AnimaticView)。

### 4.7 画布(canvas)

- 现状:403 已根治 + 前端超时/重试兜底已加;ComfyUI 浅色主题与暖黑撕裂仍在。

## 五、是否需要推倒重来

### 判断:**不整体推倒。骨架保留,两个模块定向推倒。**

理由:
1. token 层、灵动岛导航、剧场版型是三轮迭代沉淀下来的正确资产,且灵动岛是用户亲自确认过的方向;推倒等于把已验证的 70% 一并扔掉。
2. 用户"觉得一般"的根因(§1.4 C)不是方向错误,而是**覆盖率不足**——玻璃/剧场/动效只做了生成三视图,其余 15 个视图还在上一个时代。
3. 真正该推倒的两块有明确边界:NSFW 双体系(4.4,合并式重做)和 DramaStudio/Manju(4.6,删除式重做)。这两块完成后,legacy token、双轨字号、Fraunces、样式三分天下全部解锁清零。

### 若未来仍要整体重构,前提条件(现在不满足)

- 出现"单页 SPA + ?view= 路由"无法承载的需求(如 SEO、多 tab 协作深链)时,才值得迁 Next.js 多路由 + 完整设计系统重写。当前无此需求。
