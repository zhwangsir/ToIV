# ToIV 多模型搭配可控方案（角色槽 · 配方 · 库存）

> 日期：2026-10-25（Asia/Shanghai）  
> 状态：**P0.5→用户自选纠正已落地（本地未 commit）· LoRA 挂件最小可用 · P1 库存 API/生成接线待继续**  
> 触发：设置页 P0（三区）落地后，用户反馈「可控性太差」——设备上模型很多，**不同任务要不同搭配，不知道该怎么控**。  
> 关联：[`SETTINGS_REDESIGN_PLAN_20261025.md`](./SETTINGS_REDESIGN_PLAN_20261025.md) · IA 规格设置=模型露出点 · LingGuo 简洁主路径 + 受控专家层 · 个人学习站

## 0. 一句话答案

**不要在设置里继续堆「又一个模型下拉」。**  
用三层心智控搭配：

| 层 | 名字 | 用户问的是 | 默认可见？ |
|----|------|------------|------------|
| A | **角色槽（Capability slots）= 主控** | 「剧本 / 出图 / 出视频 / 配音…**各自**现在用谁？」每行自选候选 | 常用 · 必见 · 下拉 |
| A′ | **LoRA 挂件** | 「这个基座上还叠哪些 LoRA？」挂在出图/视频槽下，不是并列主槽 | 常用 · 槽下「管理」 |
| B | **快捷示例（可选，非最优）** | 「先给我一组起点，我再改」 | 常用 · **次要折叠**；点了只是预填 |
| C | **库存（Inventory）** | 「集群里还有哪些、是否在线？」 | 模型与算力 · 只读 |

URL / 端口 / 自定义云渠道 / NAS 换权重 → **高级或「更换」抽屉**，不进常用瀑布。

## 1. 痛点重述（对照 P0 后仍弱的点）

P0 解决的是**信息架构噪音**（瀑布、端口、渠道过重），**没有**解决「多模型怎么搭配」。

| # | 仍弱 | 证据 |
|---|------|------|
| C1 | **默认只有粗能力 4 格** | `ModelDefaultGrid`：`text/image/video/audio`（+助手）。VLM、TTS、超分、ASR、H3 vs Wan/Animate **没有独立槽** |
| C2 | **下拉=渠道模型大杂烩** | 按 capability 过滤渠道模型列表；用户分不清「默认视频」是 H3 还是 LongCat，还是 NAS 刚绑的权重名 |
| C3 | **算力绑定 ≠ 角色选用** | `LocalComputePane` 管 NAS 换模（出图/视频/H3）；常用区的「默认模型」又是另一套；两套心智打架 |
| C4 | **无整套配方** | 能力地图已点名「推荐组合（小/大显存）未产品化」；代码里只有 RH 应用 preset / 画布视图 preset，**没有跨角色的算力配方** |
| C5 | **库存在 Admin，创作台看不见** | `fleet` / Observability 运维向；设置页只有 compact 三态条，不够「我有很多模型」的浏览与健康 |
| C6 | **同卡冲突无产品提示** | Mia `:8888` 与 dsv4 `:8000` 互斥（现网 Mia LIVE、dsv4 停）；设置不提示「换对话 LLM 家族=停另一路」 |

用户原话要回答的是 C1–C4，不是「再多分一个 Tab」。

| 角色槽（建议 id） | 现网主路（2026-10-25） | 机器 | 备注 |
|------------------|------------------------|------|------|
| `llm.chat` | Mia TensorFold · served `DeepSeek-V4.1-Flash-1017` · `:8888` | spark02(+spark01 TP) | 与 dsv4 `:8000` **同卡互斥**；proxy 可改写旧别名 |

## 3. 推荐心智模型

```
角色槽 Slots（用户自选）  ◄──主控──  每行下拉从候选挑选
        │
        ├─ LoRA 挂件：挂在出图 / 视频主 / 视频运动槽下（多选+强度）
        ├─ 快捷示例（可选）：仅预填，不保证最优；手改后取消高亮
        ├─ 短剧工作台：消费槽位默认；单镜可临时覆盖
        ├─ 自由画布（专家）：节点级再选模型
        └─ 更换 / 高级：改权重、URL、云渠道
库存 Inventory ──只读──►  「还有什么、在不在线」；点「用于某槽」才写入
```

### 3.1 角色槽（常用主表）

每个槽一行：**角色名 · 当前选用（友好名）· 状态灯 · [更换]**。

P0.5 最小可见集（学习站够用）：

1. 对话 / 剧本 LLM  
2. 识图 VLM  
3. 出图  
4. 出视频（主：H3）  
5. 出视频（运动备选：Wan/LongCat/Animate…）— 可折叠为「视频 · 更多引擎」  
6. 配音 TTS  
7. （可选一行）助手 — 跟随对话 LLM

暂不进常用：超分、Embed、Demucs、JoyCaption、自定义云 — 进库存或高级。

**实现映射（避免大重构）：**

| 槽 | 近期后端键 | 说明 |
|----|------------|------|
| 对话 LLM | `textModel` + 系统 `/api/llm` | 已有 |
| 助手 | `assistantModel` | 已有 |
| 出图 | `imageModel` + NAS image bind | 已有 |
| 出视频主 | `videoModel` 当 H3/toiv-h3 时 | 需文案拆清 |
| 出视频运动 | 渠道 `toiv-video-wan` 引擎分类 | `classifyLocalVideoEngine` 已有 |
| VLM / TTS | **今日无用户级 override** | P0.5 先**只读展示系统绑定**；P1 再可写 |

### 3.2 快捷示例（可选 · **非最优保证**）

> 用户纠正（2026-10-25）：搭配不能固定死；除非能证明最优，否则必须让用户自选。芯片只能当「可选快捷」。

三条内置仅为**起点示例**（名字已改为「短剧起点 / 偏质量 / 偏省显存」）：

| id | 名称 | 意图 | 典型预填 |
|----|------|------|----------|
| `drama-default` | 短剧起点 | 可选起点 | Mia LLM · H3 · 本地出图 · Wan 运动 |
| `quality-slow` | 偏质量 | 可选起点 + 少并行文案 | 同上主路 |
| `vram-save` | 偏省显存 | 可选起点 + 少并发文案 | 同上主路 |

行为：

- **默认折叠**在槽位表下方；文案写明「可改 · 非最优保证」。  
- 点芯片 → 确认「预填（仍可改）」→ 写入槽位；用户随后逐槽修改会清掉示例高亮。  
- **禁止**把示例当唯一/主控，禁止文案暗示「这就是最优」。  
- **冲突**：Mia vs dsv4 互斥横幅保留——**不自动 docker 起停**。

### 3.4 LoRA 控制（挂件模型）

LoRA **不是**与对话/出图并列的第 N 个主槽（会炸屏），而是挂在**出图 / 出视频·主 / 出视频·运动**基座上的附加权重。

| 问题 | 答案 |
|------|------|
| 库存在哪？ | NAS `toiv/comfyui-models/loras/`（盘扫约 262）+ `h3/loras/`；策划卡 `lora_catalog`（Wan/H3/LTX 点名文件，**不**枚举整目录） |
| 现有产品入口？ | 市场/生成台 `type=loras`（H3 运行时枚举 / Wan·LTX 策划清单）；画布 style-profile LoRA 资产；出图多为提示词 `<lora:名:权重>` |
| 设置页最小可用（已做） | 槽下「LoRA 挂件」行：展示已选 ·「管理」多选（≤3）+ 强度；候选优先 `GET /api/models/engines` 的 loras options |
| 现在不能做什么？ | 出图引擎无结构化 loras 参数 → 设置页诚实空态；钉选暂存 localStorage，**尚未**自动注入每次生成；NAS 全量按基座过滤浏览 = **P1** |
| 与自选基座关系 | 先选槽位基座，再挂 LoRA；换基座不自动清空挂件（用户可在管理里清）；生成接线时须校验 LoRA 是否适配该基座/引擎 |

### 3.3 库存（Inventory）

「模型与算力」页上半：按**类型**分组的只读卡片（对话 / 视觉 / 语音 / 出图 / 视频 / 其它），每项：友好名 · 在线/离线 · 「用于…」下拉写入对应槽。  
下半：现有 LocalCompute「更换」抽屉（NAS 绑定）— 主列表改为只读当前绑定 + [更换]。

端口仍不进产品主文案。

## 5. 设置页 vs 短剧工作台

| 谁 | 管什么 | 不管什么 |
|----|--------|----------|
| **设置 · 常用** | 全局默认槽 + 配方 + R18 + 算力三态 | 单镜临时模型、分镜内容 |
| **设置 · 模型与算力** | 库存浏览、NAS 换权重、绑定进度 | 写剧本、点生成 |
| **设置 · 高级** | 云渠道、Key、诊断 | 日常换默认 |
| **短剧工作台** | 阶段推进；管线 ref2va/c（项目级）；单镜覆盖（P1）；忙闲/hold 人话 | 舰队端口、装模、改系统 LLM URL |
| **自由画布** | 节点级模型（专家） | 学习站默认进门 |
| **Admin** | 舰队深潜、作业 hold、装模运维 | 创作者日常搭配 |

原则：**主路径改槽/配方；专家改节点；运维改舰队。** 三者不要挤同一瀑布。

## 7. 落地节奏

### P0.5（最小补丁 · 建议下一刀，仍可不 commit）

目标：让用户**看见「角色 × 当前选用」**，不必先写完整 preset 后端。

1. 常用区：把 `ModelDefaultGrid` 改成 **槽位表文案/结构**（同一套 `text/image/video/audio` 键），行标题改为角色名（对话/出图/出视频/配音…）。  
2. 增加 **只读行**：VLM、TTS（文案来自 `local-model-defaults` / 系统说明，不写新 API）。  
3. 顶部加 **配方芯片 UI**（先本地 state / localStorage）：点「短剧默认」→ toast「将恢复：Mia + H3 + 本地出图…」并写入已有 default 键；高质量/省显存可先做文案预览。  
4. 常用底加 **互斥提示条**（Mia vs dsv4）。  
5. 「模型与算力」页头加一句：「这里是库存与换权重；日常搭配请回常用。」

**明确不做（P0.5）：** 新后端 preset 表、自动 docker 切 LLM、大拆 LocalCompute、Admin 搬家。

### P1

1. Preset 持久化（用户级 JSON / config store）。  
2. 库存只读列表接 fleet 摘要（无端口）。  
3. NAS 主列表只读 + 更换抽屉（原 SETTINGS P1）。  
4. 短剧项目级「覆盖出视频引擎」入口（工作台，非设置瀑布）。

### P2

1. 自定义配方；槽位可写 VLM/TTS override。  
2. 与 LingGuo 主路径同壳；节点专家层选模与全局槽双向可见「来自配方 xxx」。
